Zenith Team is a Go server plus a pnpm workspace for the web and desktop apps. This page gets you to a running stack. The rules for issues, commits, sign-off and pull requests live in [CONTRIBUTING.md](https://github.com/Intelligent-Internet/zenith-team/blob/main/CONTRIBUTING.md), and the engineering rulebook is `AGENTS.md` in the repository root. Read both before you open a pull request.

## Requirements

- **Go** 1.26
- **Node.js** 24 (`.nvmrc`; Electron needs 22.12 or newer)
- **pnpm** 9.14.2: `corepack enable` picks the pinned version
- **Docker** for the local PostgreSQL, Redis and Silo stack, and for the integration tests
- **`codex` or `claude`** on your `PATH` if you want to run agents

`server/go.mod`, `.nvmrc` and `frontend/package.json` are the source of truth for versions. `make doctor` checks what you have.

## Run the stack

Give each long-running command its own terminal.

1. Install the client workspace once. `frontend/` is its own pnpm workspace, so install inside it:

   ```bash
   cd frontend && pnpm install
   ```

2. Start the infrastructure, the server and the web app in one terminal:

   ```bash
   make dev         # PostgreSQL, Redis and Silo in Docker, then the Go API on :8788 and the web app on :5173
   ```

   Or run `make infra-up`, `make server` and `make frontend` in three terminals.

3. Open **http://localhost:5173** and create an account.

Already run PostgreSQL, Redis and S3-compatible storage yourself? Copy `server/.env.example` to `server/.env`, point it at your services, and use `make server-local` instead.

To run agents, start a [daemon](/daemon-and-runtimes):

```bash
make zenith-team-mcp-dev   # from the repository root: build the agent tool server
cd server
go run ./cmd/zen auth login --server http://127.0.0.1:8788
ZENITH_TEAM_MCP_EXECUTABLE="$PWD/../.dev/bin/zenith-team-mcp" go run ./cmd/zen daemon start
```

The full walkthrough is `docs/quickstart.md`. Run `make help` to see every target.

## Check your change

The main checks, from the repository root:

```bash
make go-fmt-check go-unit               # Go format, build, vet and unit tests (no Docker)
make lint typecheck                     # frontend checks
make api-lint api-types-check           # OpenAPI contract and generated types
```

CI runs the PostgreSQL, Redis and object-storage suites every night, not on pull requests. Run them yourself when you change migrations, sqlc queries or test fixtures:

```bash
make go-integration                                          # all tagged suites (Docker required)
make go-test GO_TEST_ARGS='./internal/task -run TestName'    # one package or test
```

`make gate` runs every lane, including the integration suites. [Testing](/developers/testing) lists every target and what CI runs.

## Generated code

- **API types.** The HTTP contract is `docs/api/spec/openapi.yaml`, an index that points to one file per domain. After you change it, run `make api-generate` and commit the regenerated types.
- **Database queries.** After you change a migration or a query, run `make go-sqlc` and commit the result. It uses the pinned sqlc version.
- **Migrations** are append-only. Never edit one that is already on `main`; add a new one.
